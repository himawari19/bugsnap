## Super Admin: Promo Banner, Email Broadcast & Top Workspaces

All three features are monitoring + promo focused, and are low-cost / free-tier-safe.

### Storage
- **Migration `011_app_settings.sql`**: create a tiny single-row table `public.app_settings` (key text primary key, value jsonb, updated_at). Used to store the promo banner message. Apply to live DB instantly.

### 1. Global Promo Banner
- **API**: 
  - `GET /api/promo` — public; returns `{ enabled, message }` from `app_settings`.
  - `POST /api/admin/promo` — Admin-guarded; upserts `{ enabled, message }`.
- **Banner UI**: In `(app)/layout.tsx`, if `enabled && message`, render a dismissible colored banner at the top (dismissal stored in `localStorage` keyed by a hash of the message so it reappears only if admin changes it).
- **Admin UI**: A "Promo Banner" card in `/admin` with a textarea, an enable/disable toggle, and Save button.

### 2. Send Promo Email (Broadcast)
- **`POST /api/admin/broadcast`** — Admin-guarded; fetch all `public.users.email` and send the same subject/body to each via Resend. Small batch (current ~3 users) so safe on free tier. Return count sent.
- **Admin UI**: A "Promo Email" card with Subject + Body fields and a "Send to N users" button that shows a confirm dialog (since it's an irreversible email action).

### 3. Top Workspaces Ranking
- Extend `GET /api/admin/data`: add `name` to the workspaces select, and compute a `topWorkspaces` array (top 5 by capture count, with workspace name + owner email).
- **Admin UI**: A compact "Top Workspaces" card listing the top 5 near the stat cards.

All secure (admin APIs re-check SUPER_ADMIN_EMAILS on the server), no heavy queries, no DB bloat beyond one tiny settings row.
