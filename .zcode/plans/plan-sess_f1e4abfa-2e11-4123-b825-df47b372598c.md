## Delete confirmation + Google Drive deletion melalui Dashboard OAuth

Pilihan: semua single/bulk delete memakai konfirmasi, dan dashboard memperoleh Google OAuth agar dapat menghapus file tanpa menunggu extension.

### 1. Konfirmasi aman untuk seluruh delete
- Tambahkan custom modal di `src/app/(app)/captures/page.tsx` untuk single card dan bulk selection.
- Modal menampilkan judul atau jumlah capture, serta dua opsi eksplisit:
  - hapus dari Mazway dan pindahkan file Drive ke Trash;
  - hapus dari Mazway saja.
- Tidak ada operasi saat klik menu Delete; operasi baru berjalan setelah tombol konfirmasi.
- Modal tetap terbuka saat gagal, menampilkan error, dan tombol dicegah dari double-submit.
- Detail page `/v/[id]` diselaraskan ke alur yang sama.
- Validasi affected rows/returned IDs agar UI tidak menghilangkan card saat RLS sebenarnya menolak delete.

### 2. Google OAuth server-side
- Gunakan authorization-code flow Google dengan PKCE/state; jangan memakai implicit token flow dashboard.
- Tambahkan route connect/callback/status/disconnect Google Drive.
- Gunakan server-only `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, dan `GOOGLE_TOKEN_ENCRYPTION_KEY`.
- Refresh token dienkripsi sebelum disimpan; tidak pernah dikirim ke browser atau tabel yang dapat dibaca anon/authenticated.
- Scope minimum: `drive.file`, sehingga dashboard hanya mengelola file yang diotorisasi/dibuat oleh aplikasi yang kompatibel.
- Verifikasi state, authenticated Supabase user, token response, dan exact scope.

### 3. Schema dan ownership
- Tambahkan migration untuk:
  - koneksi Google Drive terenkripsi per Mazway user;
  - stored immutable Drive `file_id` pada capture (backfill dari `drive_url` bila format valid);
  - audit/idempotency deletion job.
- RLS menutup tabel token dari seluruh client; hanya server service role yang dapat membaca ciphertext.
- Tambahkan API delete single/bulk yang memverifikasi session Supabase dan ownership workspace sebelum menyentuh Drive.

### 4. Urutan penghapusan tanpa kehilangan data
- Default Drive action adalah **move to Trash**, bukan permanent delete, agar masih bisa dipulihkan.
- API memproses setiap capture:
  1. cek authorization dan capture ownership;
  2. refresh Google access token server-side;
  3. trash Drive file memakai stored `file_id`;
  4. setelah Drive berhasil, hapus capture database secara transaksional;
  5. jika Drive gagal, jangan hapus record Mazway kecuali user memilih “Mazway saja”.
- Bulk delete mengembalikan hasil per capture dan mempertahankan card yang gagal.
- Idempotency mencegah retry mengeksekusi penghapusan dua kali.

### 5. Kompatibilitas penting
- File saat ini dibuat oleh OAuth client extension. Google `drive.file` bisa bersifat app/client-sensitive; dashboard OAuth harus memakai Google Cloud project/client strategy yang kompatibel dan perlu diuji terhadap file existing.
- Jika Google menolak file lama, modal menampilkan alasan dan opsi “hapus dari Mazway saja”; tidak mengklaim Drive sudah terhapus.
- Extension tetap dapat upload seperti sekarang; kontrak upload ditambah agar menyimpan `file_id` secara eksplisit untuk capture baru.

### 6. Verifikasi
- Test input/auth/state/encryption helpers, unauthorized workspace, malformed Drive URL, missing connection, token refresh failure, partial bulk failure, retry/idempotency, dan Mazway-only fallback.
- Jalankan dashboard typecheck/lint/tests/build dan extension verifier bila payload upload berubah.
- Uji OAuth menggunakan Google test credentials/local redirect dan Supabase staging; jangan menerapkan migration/token ke production tanpa backup dan approval terpisah.

### 7. Delivery
- Tetap hormati instruksi saat ini: **jangan commit atau push** sampai diminta.
- Perubahan UI lokal yang sudah ada (sidebar icon/badge, media gray stage, lightbox cleanup, compact DevTools) dipertahankan dan tidak dicampur secara tidak sengaja dengan deploy production.
